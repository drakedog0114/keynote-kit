# 出片质量指南（可编辑优先）

目标变了：**可编辑性 + 排版精度**优先，效率其次。下面是在这个前提下「哪种元素什么时候用」的决策表。

## 决策表

| 你要做的东西 | 用什么 | 可编辑 | 为什么 |
|---|---|---|---|
| 封面标题、章节标题 | `text` + `slot:"title"` | ✅ | 继承母版字号/字体/位置 |
| 正文段落、要点列表 | `text` + `slot:"body"` | ✅ | 继承项目符号、左对齐、段间距 |
| 需要自定义位置的文字块 | `text`（裸文本框） | ✅ | 但**对齐只能居中**，Keynote 不开放 |
| 彩色卡片、色块容器 | `card` | ❌（文字已栅格化） | Keynote 形状没有填充色 API |
| 数据图表 | `chart` | ❌ | matplotlib 渲染 |
| 流程图 / 泳道图 | `diagram` | ❌ | 同上 |
| 截图、照片 | `image` | ❌ | 本来就是图 |
| 结构化数据 | `table` | ✅ | 原生表格，单元格可改 |

## 三条硬规则

1. **能用 slot 就别用裸 text**。裸文本框无法设对齐（`alignment` 只对表格单元格开放，
   text item 和 paragraph 都报 -1700），默认居中，长段落很难看。
2. **slot 页不要清空、不要插整页背景**。占位符在图层最底部，任何后插入的整页图都会盖住它；
   背景交给母版。
3. **card 只做装饰**。它把文字画进 PNG，客户改不了文案；需要改字的地方一律用 slot。

## 已验证的负面结果（别再试）

| 想做的事 | 结果 |
|---|---|
| `set alignment of text item` / `paragraph` | -1700，类型转换失败 |
| RTF 直接赋给 `object text` | -1700，rich text 不接受 RTF data |
| RTF 走剪贴板 + Cmd+V | 能贴，但落点不可控（会覆盖当前占位符） |
| `duplicate text item` 复制占位符 | -1700 / Shap... 错误，不支持 |
| `make new text item` | -10000，动词损坏 |

结论：**Keynote 只给两套主题文本样式（title / body）**，想要更多左对齐可编辑文本块，
只能在母版里多放占位符（自定义版式），脚本侧无法凭空生成。

## 版面自检清单（出片前过一遍）

- [ ] 所有正文是否落在 slot 里（而不是裸 text 居中）？
- [ ] 图片是否被拉伸？`apply_page` 会自动按比例修正高度，但 box 太窄仍会裁切
- [ ] 图表是否贴边？裁掉透明边后内容会真正填满 box
- [ ] 卡片文字是否需要在 Keynote 里改？要改就换 slot
- [ ] 导出 PNG 逐页看一眼，别只看文件能否打开
